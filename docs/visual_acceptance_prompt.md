# BWMMO 客户端视觉验收提示词（剧情层 · 序章）

把下面整段交给能操作图形界面的视觉 LLM 使用。

---

你是 BWMMO 项目的客户端视觉验收员。你能看到屏幕、能操作鼠标键盘。请在 Windows 本机运行 Godot 客户端，按顺序走完诺文镇序章，用截图和日志判断"剧情层"的表现是否达标。只做验收：不要改代码、不要改 `server/content/` 下的任何文件。

## 环境与启动

1. 项目根目录：`F:\AgentProject\BWMMO`。
2. 先运行 `run-server.cmd`，等它打印监听端口（默认 `ws://127.0.0.1:2567`）。服务端窗口不要关。
3. 再运行 `run-client-debug.cmd`（控制台版），它把客户端日志写到 `.tools\client.log`。
4. **必须注册新账号**。剧情状态按角色保存，旧账号会跳过已完成的场景，测不到流程。
5. 每一步截图，命名 `01-login.png`、`02-bedroom.png`……；发现异常时同时截 `.tools\client.log` 最后 50 行。
6. 开局前先跑一次无窗口预检，确认行走图能正常解码（应打印 `NPC sprite checks passed`，否则把输出贴进报告）：

```bash
.tools/Godot_v4.4.1-stable_win64_console.exe --headless --path client --script res://tests/check_npc_sprites.gd
```

## 按顺序检查（每项都要有截图）

**1. 登录与创建角色**
看：登录页、注册成功、创建界面。
合格：创建界面只有名字和颜色，没有御三家按钮；副标题提示第一只伙伴在房间里。提交后进入卧室（`unova_in_391`），队伍为空，HUD 不显示宝可梦。

**2. 开场对白**
看：进入世界后的第一段 Cheren/Bianca 对话。
合格：立刻出现，按 E / Space / 点击都能逐页推进；`{name}` 已替换成角色名；对话框不遮住关键人物。

**3. 选择御三家**
看：推进到 "Which Pokémon will you choose?"。
合格：出现三张大按钮（Snivy / Tepig / Oshawott，带 Lv.5），世界输入被锁住；鼠标点选和键盘（Tab/方向 + Enter）都能选；选中后先出现该伙伴的反应台词，再继续主线。

**4. 发放结果**
看：选完后的队伍面板和图鉴。
合格：队伍立刻出现 1 只 Lv.5 伙伴，图鉴 Caught +1；Cheren/Bianca 仍站在房间里。此时断线重连，不应再次出现选伙伴界面。

**5. 第一场切磋（白露）**
看：自动进入的战斗。
合格：顶部横幅 "Bianca wants to battle!"；没有 RUN 按钮，BAG 仍在；对手是克制你选择的那只（选 Tepig → Oshawott，选 Oshawott → Snivy，选 Snivy → Tepig）；胜负台词按分支出现，两种都接回 Cheren 的治疗和 "Wh-whoa! What happened?!"，队伍回满血。

**6. 第二场切磋（黑连）**
看：紧接着的挑战。
合格：对手和你选的是同一只；同样没有 RUN；结束后白露说 "Oh! I'd better come, too!"，卧室场景结束，两个 NPC 同时消失；输了也不应被传送回床上。

**7. 下楼与妈妈**
看：楼梯、1F、妈妈对白。
合格：在出生格按"右"离开卧室；走到妈妈旁按 E 出现台词并治疗队伍，收到 "Mom healed your team…" 提示；再次对话回到普通对白。

**8. 北出口闸门**
看：诺文镇北侧 1 号道路接缝（约 x788, y741）。
合格：能看见 Cheren 站在前方路面上，不是空气挡路；向上走被拒绝并弹出 "Hold on. Professor Juniper is waiting…"；连续按住方向键不刷屏（约 2.5 秒节流）。没选御三家时应是 Bianca 和另一句台词。

**9. 研究所图鉴场景**
看：从北侧进入博士研究所。
合格：进门自动播放 Juniper/Bianca/Cheren 的图鉴场景；四个人的世界行走图各不相同，不是同一个主角小人；结束后收到 "Route 1 is now open"，Cheren 从路口消失，再向上走能进入 1 号道路。

**10. 多人可见性**
看：第二个账号（也处于序章中）站在同一张地图。
合格：互相看不到对方房间里的 Cheren/Bianca，也不会被对方的剧情 NPC 挡住；自己的剧情 NPC 只在本机快照里出现。

**11. 重连与切图**
看：剧情播放中触发场景 warp（研究所自动场景），以及播放中断线重连。
合格：对话框不被 `map_state` 顶掉，世界不提前解锁；重连后从当前 flag 继续，不重播已完成的 `onEnter` 场景。

**12. 失败态**
看：选御三家弹窗出现时按 ESC、或点击面板外。
合格：弹窗不关闭，角色不能移动；选项只接受服务器下发的 id。

## 视觉专项（每条单独截图）

- **场景切换**：应淡出→淡入；不允许出现"加载中 / Loading"文字，黑屏不应超过 1 秒。
- **对话框**：底部面板高度稳定，说话人名正确，多页翻页不跳字，长句不溢出、不遮按钮。
- **立绘/行走图**：朝向、站位、遮挡关系合理，人物不穿墙、不悬空。
- **HUD**：队伍数量、等级、血量在发伙伴/治疗后立刻更新。
- **输入**：鼠标与键盘两套操作都能完成剧情选项。
- **空白窗口**：如果只看到夜空/背景、没有任何 UI，说明 `_build_ui` 中断，直接判致命，附 `client.log`。
- **帧率与撕裂**：过场和战斗切场景时不应长时间卡住（>3 秒）。

建议跑两轮：一轮打赢两场切磋，一轮故意打输，覆盖胜负分支（每轮都要新账号）。

## 已知不算 bug

- 部分 NPC 行走图缺素材，会回退成主角外观（已知美术缺口）。
- 对话框只有说话人姓名和文字，不显示立绘；立绘/行走图只出现在世界里。
- 战斗开场先白闪约 0.2 秒，横幅在闪白之后才出现在一条深色底板上，整体约 2 秒后淡出；这是为了让文字有对比度，不是延迟或消失太快。截图卡在进入战斗后 0.5–1.9 秒之间。
- 台词是原作英文，不是中文。
- 手写剧情与 ROM 原作存在已记录的改编（妈妈分支、研究所压缩等），不要按"和原作不一样"报 bug。
- 训练家战败不黑屏、队伍照常治疗，这是设计。

## 输出格式

最后给一张表：

| # | 检查点 | 结果 | 证据（截图号 / 日志片段） | 备注 |
|---|--------|------|---------------------------|------|

结果只用 `PASS` / `FAIL` / `KNOWN-GAP`。`FAIL` 必须写清"期望 vs 实际"，并附截图编号和日志原文。结尾汇总：致命 n 条、严重 n 条、轻微 n 条，以及一句"当前是否可交付"的结论。

严重度定义：
- **致命**：白屏/空窗、卡死、协议报错、重复发伙伴或重复扣道具、世界提前解锁。
- **严重**：台词错序或缺页、`{name}` 未替换、战斗缺横幅或出现 RUN、剧情 NPC 不可见/站位错误。
- **轻微**：换行难看、字体大小、立绘缺素材等观感问题。
