# Content localization

`zh_CN/names.json` is generated by `tools/fetch_pokeapi_zh.mjs`.

- `species`: generated from PokeAPI GraphQL `zh-hans` names, keyed by content species id.
- `moves`: generated from PokeAPI GraphQL `zh-hans` names, keyed by content move id.
- `items`: generated from PokeAPI REST item names, keyed by content item id.
- `shops`, `maps`: keyed by content id; map/NPC translations use the project glossary.
- `locations`: English names from the ROM outdoor matrix (field 14 of the zone header) to display names; the grid itself is `content/rom/outdoor_locations.json`.
- `npcs`: keyed by the English NPC name from the map files, including story
  speakers and gate speakers. Map furniture labels (`TV`, `Furniture`, ...) live
  in the same table so the examine box shows a localized object name.
- `abilities` / `abilityDescriptions`: keyed by Showdown ability id; generated
  by `npm run build:ability-i18n` (run from `server/`), which reads PokeAPI
  `zh-hans` names and flavor text and caches responses under
  `.tools/ability-i18n-cache.json`.

Names are display-only. The server keeps canonical English names in saves and
only replaces them on outbound client payloads, so switching languages never
mutates persisted characters.

Regenerate after changing content or the glossary:

```bash
node tools/fetch_pokeapi_zh.mjs
cd server && npm run build:ability-i18n
```

The script caches GraphQL and item responses under `.tools/pokeapi-cache/`.

## Dialogue

`zh_CN/dialogue.json` holds NPC, gate and story dialogue translated into
Chinese. Blocks are keyed by the canonical English lines joined with newlines,
because the translation may reflow a text segment into a different number of
pages. `ContentLocalizer.dialogue(locale, lines)` returns the translation or the
original array when a block has no entry.

- `dialogue.json` is generated by `tools/rom/build_dialogue_zh.py` from the
  PokeMMO community Chinese language pack. That pack dumps its storyline
  strings with the ROM's own text table ids (`table_id` = text archive member,
  `block_id`/`entry_id` = segment), so translated segments map onto the
  segments the BW field script prints. The generator also normalises the
  pack's terminology (精灵→宝可梦, 训练师→训练家) and punctuation to match the
  rest of the project.
- PokeMMO adapted some scenes, and its dump does not always have the same
  empty slots as the retail ROM. Per text table the generator picks the
  reading that matches the dump's entry count (section ids, or the ordinal
  among non-empty sections). Tables that match neither are skipped, and so are
  tables whose argument placeholders do not line up with the English text;
  those scenes fall back to English instead of showing a mismatched line.
- `dialogue_manual.json` holds hand-written translations for project-authored
  service, story and map-object dialogue; it is loaded after the generated
  table and wins on conflicts. The map-object part is the fallback examine text
  (`It's a TV.` → `是一台电视。`) plus the few object scripts the local VM did
  decode.

The pack comes from the community thread
`forums.pokemmo.com/index.php?/topic/107378` (简体/繁體语言汉化包) and is not
committed: place the extracted mod under
`.tools/pokemmo-zh/mod/custom-strings/` and run

```bash
python tools/rom/build_dialogue_zh.py
```

The generator skips blocks whose English text is shared by two scenes with
different translations (for example a bare "...") rather than guessing; add
those to `dialogue_manual.json` if a scene needs them. `server/test/i18n.test.ts`
fails when any shipped NPC, story or map-object line — or any object label —
has no Chinese block.
